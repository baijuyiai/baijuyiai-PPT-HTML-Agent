# 右栏图片面板：认出新链路的图位，并让它们可编辑

## 起因

右栏的图片面板对新链路页面**完全失灵**。它只看 `page.blocks`（旧链路的结构化块），
而新链路页面里 `blocks` 是空的——内容全在 `page.html` 里。实测那本 30 页的书，
**每一页的 `blocks` 都是空数组**，所以不管点哪一页，面板都显示
「本页没有图片槽位。可在左栏把页类型改为「图文」，或重新生成这一页」——
而其中 5 页其实有图位，共 7 个（封面 1、图片排版 1、图文 2、人物 3）。

用户要的：**当前页面如果有图片，右栏应该能识别、修改、重新生成、抠图、调整位置、删除、新增。**

## 一、图位从哪来

解析 `page.html` 里所有 `data-lumen-image="n"`，每个图位带四项：

- `n` —— 就是 `fillImageSlots` 取图用的那个下标（从 1 起）
- `cutout` —— 是否透明底（判据见「图位分池」那份 spec：显式标记，或样式里写了 `object-fit: contain`）
- `src` —— 当前落的是哪张：覆盖表里有就用它，没有就是素材库按色板自动配的那张
- 几何 —— 画布坐标系（1920×1080）里的 x / y / w / h

几何的取法：**iframe 是 `sandbox="allow-same-origin"`，父文档可以直接访问
`contentDocument`**（实测过）。编辑器里从 iframe 里读 `getBoundingClientRect()`，
再按画布的缩放比例换算回 1920×1080 坐标。演示态与导出不需要几何，不读。

旧链路的 `blocks` 里那些 image 块**继续认**，但两条路不混：一份页面要么走 HTML
要么走 blocks，面板按「有 html 就解析 html」分流。

## 二、存哪：`PageIR.overrides.images`

`PageIR.overrides` 这个字段已经有了（`page.ts:355`，`z.record(z.unknown())`）。
往里放一份按图位序号索引的覆盖表：

```ts
interface ImageSlotOverride {
  src?: string;            // 换成这张
  cutout?: boolean;        // 透明底
  hidden?: boolean;        // 不要这张图
  dx?: number; dy?: number;   // 挪动图位本身（画布像素）
  scale?: number;             // 缩放，1 为原样
  rotate?: number;            // 追加旋转（度）
  focus?: { x: number; y: number };  // 图在框内的裁切中心（0–1）
  zoom?: number;              // 框内放大倍数，1 为原样
  prompt?: string;            // 重新生成用的提示词
}
```

**为什么不直接改模型写的 HTML**：

1. 模型 HTML 是重生成的产物，直接改它不可逆——用户手调过的图会在下一次重生成时
   无声消失，而且没有任何地方提示过这件事；
2. `fillImageSlots` 本来就会**覆盖**图位上写着的 `src`（`html-doc.ts:110-113`），
   把 src 写进 HTML 根本活不下来；
3. 覆盖表可逆、可保留、能集中在一处实现——画布、演示、导出、样机四条渲染路径
   都经过 `buildPageDocument`，改一处全都吃到。

渲染时 `fillImageSlots` 优先用覆盖表，没有的项再走素材库自动配。**覆盖表按序号索引**，
所以模型重生成后如果少写了一个图位，多出来的覆盖项自然失效（不报错，只是不生效）。

## 三、七个操作怎么落

| 操作 | 落法 |
|---|---|
| 识别 | 解析 HTML + 从 iframe 读几何，只读 |
| 修改 | 写 `src`。来源两处：素材库挑一张（复用挑图那套色板匹配）、上传自己的（走已有的 `POST /uploads`） |
| 重新生成 | 面板里写提示词（**留空时用页面标题 + 主张自动拼一句**）→ 调图像模型 → 结果存对象存储 → 写 `src` |
| 抠图 | 本地抠底（与「图位分池」那份 spec 同一套管线）→ 新文件 → 写 `src` + `cutout: true` |
| 调位置 | 面板滑杆 + 画布拖拽 → `dx/dy/scale/rotate`。渲染时用 **`translate` / `scale` 独立属性**叠加，**不动模型写的 `transform` 简写**——简写会被整个替换掉，而模型常用 `transform: translate(-50%,-50%)` 居中（`STAGGER_CSS` 的注释里记着这个坑） |
| 调裁切 | `focus` + `zoom` → `object-position` 与尺寸。**只在图位自己没有写 `object-position` 时才注入**，不抢模型的选择 |
| 删除 | `hidden: true`。渲染时把这个 `<img>` 整条移除（不是留占位块——用户说不要了，就不该还占着一块地） |
| 新增 | **唯一一处要改模型 HTML 的操作**（见下）。往 HTML 里插一个**绝对定位**的 `<img>`（不参与文档流，不会把模型的版挤乱），默认落在右下角，再用「调位置」挪过去 |

### 「新增」为什么是例外

前六项都能靠覆盖表表达，因为**元素已经在那儿了**——覆盖的语义是「这个图位改成这样」。
新增没有元素可覆盖，只能往 HTML 里插。所以它有两个额外的麻烦，也是把它放到 P3 的理由：

1. 插进去的元素在下一次**重新生成页面**时会消失（整份 HTML 被换掉）。要在界面上说清楚
   这件事，不能让用户以为它跟别的调整一样会留下来；
2. 插入位置的默认值要保守——绝对定位 + 右下角 + 一个不太大的尺寸。做小了用户自己挪，
   做大了会盖住模型排的内容。

## 四、画布上直接拖

- 父文档从 `contentDocument` 读图位的几何，在画布上叠一层透明手柄（手柄画在
  iframe 之外，与装饰件、数字人同一个坐标系）。
- **拖动时直接改 iframe 里那个元素的内联样式**——不重载 iframe，所以是跟手的。
  重载 `srcdoc` 每帧一次会让拖动变成幻灯片。
- 松手把 `dx/dy` 写进覆盖表，走正常渲染（这时才重载一次，落在最终位置）。
- 拖拽只在编辑态生效；演示态与导出没有手柄。

## 五、分三段做

| 段 | 内容 | 验收 |
|---|---|---|
| **P1** | 识别 + 修改 + 删除 | 面板列出 7 个图位（含缩略图与几何），能换图（素材库 / 上传）、能删。「撤销」= 清掉该图位的覆盖项、恢复素材库自动配图 |
| **P2** | 抠图 + 重新生成 | 能把一张图抠成透明底；能按提示词生成新图并落到该图位 |
| **P3** | 调位置 + 调裁切 + 新增 | 面板滑杆与画布拖拽都能挪图位；能调框内裁切；能新增图位 |

每段各自能独立上线、独立验收。

## 六、验证

1. `pnpm test`、`pnpm -r typecheck`、`pnpm build` 全过。
2. 单测：
   - 图位解析：多图位、跳号（模型常写 `<img data-lumen-image="2">` 而漏了 "1"）、
     重复下标（实测有五连 "1"）、上传图（有真 src、无 `data-lumen-image`）；
   - 覆盖表优先级：有覆盖用覆盖，没有走素材库；`hidden` 时元素整条消失；
   - `dx/dy/scale` 叠加后**不覆盖模型自己的 `transform`**（这条最容易悄悄坏）；
   - 覆盖表项与图位对不上时（模型少写了图位）不报错、只是不生效。
3. **真浏览器实测**（按仓库规矩）：打开那本书的封面页，面板应列出 1 个图位；
   换一张图后画布立即变；删掉后图位消失；撤销后回来。旧代码当对照组。

## 不做

- 不改模型写的 HTML——**唯一例外是「新增」**（见第三节，那一条没有元素可覆盖）。
- 不在 iframe 里开 `allow-scripts`（安全边界不动）。
- 不做「把图位从一页搬到另一页」。
- 不做图层顺序调整。
